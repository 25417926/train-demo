## 6. 可重复执行脚本

```powershell
# 1) 生成本地令牌（若无 sk_token 记录）

  -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body))

# 3) 串行受理压测
$order = @{ date='2026-06-10'; trainCode='G105'; start='西安'; end='南京'
  dailyTrainTicketId=2064071105601212416
  tickets=@(@{ passengerId=2064056182418575360; passengerType='1'; passengerName='11'
                passengerIdCard='11'; seatTypeCode='1' })
  code='1234'; codeToken='token-x' } | ConvertTo-Json -Depth 5
1..20 | ForEach-Object {
  $sw=[Diagnostics.Stopwatch]::StartNew()
  $r = Invoke-RestMethod -Uri 'http://127.0.0.1:8081/business/web/confirm-order/do-storage' `
    -Method Post -Headers @{ UserId='2064044044501258240'; 'Content-Type'='application/json' } `
    -Body ([Text.Encoding]::UTF8.GetBytes($order)) -TimeoutSec 15
  $sw.Stop(); "{0} {1}ms {2}" -f $_, $sw.ElapsedMilliseconds, $r.content
  Start-Sleep -Milliseconds 100
}
```

## 7. 已知问题与风险

1. **令牌 DB 兜底未命中**：Redis 中不存在 `token_count_*` 时，`Sk_TokenService.validToken` 走数据库兜底分支但返回 false（未观测到 `SET token_count_*`，`sk_token` 表 count 也未递减），导致受理直接返回 409「当前抢票人数过多」。正常流程由 `genDaily` 预置 Redis 计数可规避；该分支需在令牌改造（I05/I06）时排查。
2. **member 未注册 Nacos**：当前 `MemberFeign` 仍硬编码 `http://127.0.0.1:8080`，出票依赖 member 本地启动；I10 修正为服务名调用后需保证 member 注册到 `train` 命名空间。
3. **基线会写入真实数据**：本轮在 `train-business.confirm_order` 新增 21 单（status=S），`train.ticket` 同步新增 21 张票，仅用于基线留档。
4. **maxmemory 512mb**：当前数据量远小于限额；后续库存 key 上线需按容量重新评估并接入监控。
